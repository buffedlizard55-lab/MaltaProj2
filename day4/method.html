Method & sources

Fixture discovery (the lobby, reverse-engineered)

The HotSpawn pick'em lobby renders from a JSON state bundle; the underlying fixtures API (phpstack-1372681-6459848.cloudwaysapps.com/api/v1/fixtures) accepts exactly three filter parameters — sport_alias, status and competition_id (discovered this session; from, limit and tier are rejected with 400 "property should not exist"). The competition_id filter returns a small single-chunk JSON per tournament, which is how this desk captures cleanly: seven per-competition captures cover every open fixture. The unfiltered response spans 9 chunks and mixes in stale rows. Every raw response is retained verbatim under data/1c8f79f8/evidence/ before any derivation.

Verified API fields per row: id, competition_id/name, scheduled_start_time/lock_time (ms epochs; lock = start − 360 000 ms, i.e. the 6-minute lock verified via lock_offset_sec=360), offered_points/base_points (tier B = 3 offered, tier C = 2; points_breakdown = game 1.25 × tier (B 1.5 / C 1) × series/stage/tournament 1), tier (a/b/c), stage, total_picks, and per-participant id/name/picked_percent/score. Epoch anchor re-verified this session: 2026-10-17T00:00Z = 1792195200 s; the lobby renders times in US-Eastern, so "Oct 17, 04:00" on a card is 08:00Z.

Probability policy (three bases, never blended silently)

  1. Market — a real two-sided price from a venue (Polymarket exchange moneyline; bc.game / bookmaker averages via egamersworld; stavka.tv Russian bookmaker consensus; kushvsporte aggregate). The published fair share is the de-vigged price: p = (1/dec) / Σ(1/dec). Volume is recorded; $0.00-volume Polymarket seeds are evidence, never lines.
  2. Model — the canonical site Valve-VRS model, identical arithmetic to scripts/fe803b80/core.py (Valve's glicko constants: a 400-point rank delta = 90% win chance, Q = ln(10)/400, fixed RD = 75) with the fitted scale k = 0.25 from the fe803b80 calibration block. Used only when both teams are unambiguously present in Valve's official standings with matching rosters.
  3. Blank — where neither basis is eligible, the probability stays empty and the row says why. A pick direction may still be given from verified context and is labelled directional.

HotSpawn crowd percentages are ownership context only. They are stored on every row, displayed next to the line, and never enter any probability — asserted by tests. Where the crowd and the line disagree, that disagreement is the contrarian signal and is documented as such.

The contrarian ladder (gates, applied per row)

  • Safe pick — the best available line (market if it exists, else model).
  • Climb pick — a leaderboard swing, activated only when ALL gates hold: underdog fair probability ≥ 30–35%; crowd ownership of the picked side ≤ 20%; fair-probability/ownership ratio ≥ 2×; ≥ 2 verified context flags; capped swings per day. Three climbs activated today: Donstu, Enjoy, WBT.
  • Contrarian lean — gates documented but not all passed (e.g. ASTRAL at 24% ownership misses the 20% gate); published as a lean, never as an activated swing.

Source hierarchy

  1. Official: Valve VRS repo (github.com/ValveSoftware/counter-strike_regional_standings), HLTV match/event pages (results, lineups, live VRS forecast), tournament organizer pages.
  2. Prices: Polymarket exchange moneylines, egamersworld bookmaker averages (bc.game et al.), stavka.tv and kushvsporte bookmaker aggregates, bo3.gg (Thunderpick coefficients).
  3. Context: strafe (brackets, form, user votes — sentiment only), tips.gg, tribuna.com, esports.gg, Field Level Media/Reuters, dust2.us, Liquipedia.
  4. Never used as prices: HotSpawn crowd %, HLTV fan-vote widgets, strafe user votes, egamersworld prediction-bot votes, placeholder 1.8/1.8 pairs, $0-volume Polymarket seeds.

New listings the ledger has never seen (repair, 2026-10-16)

The board is rebuilt from the fresh fixtures capture, not from the curated ledger alone. A fixture that appears in the capture but not in the ledger gets a row automatically, priced in this order:

  1. an exact fixture-id quote retained in another published board on this site (the canonical every-match board, the full-coverage board, the ourline board, the exec board or the research-resolved board) — the sibling board's raw decimals and its public URL and read time are republished verbatim and re-de-vigged here;
  2. otherwise the canonical Valve-VRS model, when both teams are unambiguously present in Valve's official standings;
  3. otherwise a blank probability with a published reason and a note that the four-hourly collector retries every external venue.

Fixture-id equality is the join key, so no alias, sibling rating or tournament-slot guess is introduced. Live drift between the ledger and the capture — ownership percentages, rescheduled kickoffs, name rendering — is recorded on the row (inventory.drift) instead of aborting the rebuild, and a capture that returns empty or truncated keeps the last researched inventory with a retained_inventory_capture_degraded flag rather than publishing a silently smaller board.

Refresh cadence and evidence

.github/workflows/day4-1c8f79f8.yml re-runs the collector and this builder every 4 hours (cron 23 */4 * * *, inside the required 4–8 h window) and after upstream board refreshes. The collector re-captures each competition, re-applies the client-side time filter, and refuses to publish if any row's lock-time arithmetic or crowd-percentage sum fails its self-check. The builder is deterministic and network-free; tests re-derive every published number from the retained raw inputs.
