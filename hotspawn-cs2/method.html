Method & sources

What this board is

For every CS2 match in the HotSpawn Pick’em lobby we publish a pick and, whenever it can be derived from a source, both teams’ win probabilities. HotSpawn itself is used only to discover which matches exist; its crowd “picked %” is never read into any probability.

Resolution chain (first tier that resolves wins)

  1. Market line. Two-way match-winner prices are collected from Pinnacle, Bovada, Melbet, Kalshi and Polymarket. A price joins a fixture only if both team names match exactly after normalisation (case/accents/generic words like “Esports” stripped; a published alias table; or an exact same-words reorder) and the book’s start time is within 30 minutes of HotSpawn’s. Each book’s margin is removed proportionally: fair = (1/odds) / Σ(1/odds). The published probability is the median across books, so any reader can re-derive it from the listed prices.
  2. Our line (VRS model). If no book prices the match but both teams appear uniquely in Valve’s official VRS global standings (snapshot 2026_10_05), we originate a line with Valve’s own Glicko expected-win formula, P(A) = 1/(1+10^(−g·Δ/400)) at RD 75, with the slope scaled by k = 0.441 — fitted by least squares to 80 fixtures where we observed both a market consensus and two VRS ratings (mean absolute error vs the market 7.6pp; favourite agreement 82%). Valve’s unscaled curve (k=1) errs by 11.8pp on the same pairs, so we use the fitted slope. Model probabilities are capped to 3%–97% and always labelled estimates.
  3. Direction only. If only one side has a verified rating signal (or all candidate rosters of one side outrank all of the other), the rated side is the pick and the probability stays blank.
  4. Unresolved. No price and no usable rating → no pick. The match is published on the Unresolved page with the exact limitations. We never invent a percentage, and never fill a blank with 50%.

Guards against bad joins

  • No prefix/fuzzy name matching (“B8” ≠ “B8 Academy”, “WBT” ≠ “WROTBERRY”); every alias join is flagged on its row.
  • Kalshi prices are never joined: its feed has no verified kickoff time. They are shown as “seen but NOT used” evidence. The same applies to any price whose start time disagrees with HotSpawn by >30 min, and to in-play (live) prices.
  • Stored derived probabilities are never trusted: the Resolver recomputes every fair % from the raw stored prices.
  • If HotSpawn is unreachable, the previous fixture inventory is kept and the failure is logged — an empty board is never published.

Freshness

A GitHub Actions workflow ( hotspawn-cs2-d9d7627b) re-runs collect → resolve → build every 2 hours and commits only when the board changes, so picks are never more than a few hours old (target <4–8h even if GitHub drops a scheduled run). New HotSpawn fixtures are picked up automatically; matches whose lock time passes move to the “Locked” section for the record.

Known limitations

  • Model lines inherit VRS staleness (monthly snapshots) and ignore maps, vetoes, stand-ins and same-day form. Treat them as a prior, not a price.
  • HLTV blocks automated reads (HTTP 403 at last probe), so HLTV form/head-to-head is linked for manual review rather than collected.
  • Some books price a match only minutes before start; a fixture can move from “model” to “market” between refreshes.
  • HotSpawn occasionally lists fixtures as “scheduled” long after their start (see Flagged page) — we account for them but cannot pick them.
