Methodology, Reverse Engineering & 4–8 Hour Refresh Architecture

1. Reverse Engineering play.hotspawn.com/lobby

The HotSpawn Pick’em page (https://play.hotspawn.com/lobby) is an Angular SSR application that embeds its initial fixture transfer state in <script id="ng-state" type="application/json"> and queries the public REST endpoint https://phpstack-1372681-6459848.cloudwaysapps.com/api/v1/fixtures. Each CS2 fixture record provides id, sport_alias: "cs2", competition_name, tier, scheduled_start_time (UTC), lock_time (6 minutes before kickoff), status, points, and participant names. HotSpawn’s crowd pick percentages are never read or used as an indicator of match probability.

3. Automated 4–8 Hour Refresh Pipeline

The GitHub Actions workflow .github/workflows/fullpicks-51197e5b.yml runs on a 4-hourly cron schedule (23 */4 * * *), after upstream collector completions, and via manual dispatch. Each run executes scripts/51197e5b/resolve.py, rebuilds fullpicks/*.html via scripts/51197e5b/build.py, verifies all contract tests in tests/test_51197e5b.py, and commits updated artifacts to main after git pull --rebase.
