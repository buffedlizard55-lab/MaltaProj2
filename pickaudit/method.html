Probability formulas being checked

Book two-way no-vig: p_a = (1/odds_a) / ((1/odds_a) + (1/odds_b))

Valve-rating logistic: p = 1 / (1 + exp(-k · C · (points_a − points_b))) with C = Q·g(RD=75), Q = ln(10)/400 from Valve's glicko.js, and k fitted by OLS through the origin in logit space on 60 market/rating pairs (documented in scripts/f7279a54/core.py).

Pick rule: the higher-probability side; ties published as explicit toss-ups.

Research ladder used by the desks being audited

  1. Featured bookmaker consensus (Pinnacle, Bovada, Melbet, Thunderpick) — de-vigged.
  2. Regulated exchange / secondary books (Kalshi) with roster-verified name aliases.
  3. HLTV / bo3.gg identity and roster checks for alias joins.
  4. Official Valve regional standings logistic origination when no book prices the fixture.
  5. One-sided ratings become labelled bounds (≥ / ≤), never point estimates.
  6. If no source exists at all, the row stays explicitly unresolved.

Limitations

  • The build sandbox can only reach GitHub hosts; HLTV, book and exchange links are live-checked by the CI runner (PICKAUDIT_LIVE_LINKS=1) and labelled unchecked in local runs.
  • The Valve global table is monthly and can be up to ~4 weeks old; roster changes after publication are not reflected.
  • Originated model lines carry roughly ±8 pp mean absolute error (see the calibration MAE).
  • Thin or zero-volume exchange quotes are market-maker ladders, not traded consensus.
  • This audit verifies published numbers; it does not settle match outcomes or grade pick accuracy.
