Method & sources

Fixture inventory (what “every match” means)

Fixtures come from the public HotSpawn Pick'ems lobby (play.hotspawn.com/lobby): the Angular transfer-state embedded in the page (its /api/v1/fixtures response) merged with the same public fixtures API the lobby calls, CS2 only, scheduled with lock time in the future at collection time. HotSpawn is used for discovery only. Its crowd “picked %” is never copied into the snapshot and never used as a probability. The collector re-runs automatically on GitHub Actions (about every 30 min); a failed HotSpawn fetch keeps the previous inventory and flags it, never an empty board.

Featured resolution (tiers A/B) — tried first for every match

  • Bookmaker/exchange prices: Pinnacle guest API (licensed bookmaker), Bovada coupon JSON (licensed bookmaker), Melbet LineFeed (licensed bookmaker), Kalshi KXCS2GAME (CFTC-regulated exchange; only books with bid/ask spread ≤ 10c on both sides). A price joins a fixture only when both team names match after the published normalisation/aliases and the source start time is within the tolerance window. No substring matches.
  • No-vig: p_i = (1/odds_i) / Σ(1/odds_j) per source; consensus = weighted mean (Pinnacle ×2, others ×1).
  • Valve VRS model: official points from ValveSoftware/counter-strike_regional_standings 2026_10_05, Valve's own Glicko expected-win formula with its slope re-fitted to observed market prices (k = 0.411, fitted on 14 priced fixtures this snapshot; k=1 would be uncalibrated Valve). Market+model blend: 85% market / 15% model (≥2 sources) or 75/25 (1 source), in logit space — a stated modelling choice, not a source value.
  • HLTV: probed every run; the automated runner gets HTTP 403 from HLTV, so HLTV odds/prices are not ingested live and no HLTV number is ever used as a price input. HLTV public team pages and betting analytics pages are inspected independently (via the browser-based fetch tool) for corroboration of tier-C team identity, world rank and recent form. HLTV user-prediction percentages are also crowd picks — they are excluded from probability calculations, just like HotSpawn's crowd picks. Corroboration notes are saved to data/9a873ea7/hltv_corroboration.json. HLTV team pages are linked where they provide identity evidence (RoundsGG→Rounds, EAC, WBT Academy, Voca, Phantom, HAVU).
  • Polymarket: probed every run; no open CS2 match markets have been observed, so nothing is taken from it. Low-tier matches are therefore resolved by B/C below, not by waiting for Polymarket.

Fallback resolution (tier C) — only where A/B is impossible

  • Slot prices (Elisa BreakOut): where Melbet/Kalshi price the same competition + UTC start + opponent under a different team label (WhiteBIT Team / WBT Academy for HotSpawn's WROTBERRY; EA Copenhagen = EAC per Liquipedia/HLTV), the slot price's no-vig probability is used as indicative guidance. Identity is flagged; no VRS rating is used for the ambiguous slot.
  • Kalshi thin books: books rejected from featured prices for spread > 10c are used, fallback-only, as normalised bid/ask mids. Raw bid/ask is stored in the snapshot evidence.
  • RoundsGG alias: RoundsGG → Valve VRS ROUNDS (548 pts) only in fallback, blended with the thin book where one exists.
  • Sibling/floor VRS (originated): where one roster has no VRS row (LFO 10), the official points of sibling rosters in the same VRS file (LFO 7/8/9) give a probability range; the midpoint is published, labelled originated and unverified. If no siblings exist, the file's lowest points are used as a provisional floor.

Every C pick is confidence-capped (“Low”), ranged, flagged, and listed on Flagged for review with its evidence links. If no evidence of any kind exists (tier D), the probability is left blank — never invented.

Verification

Unit tests (tests/test_c64a5e19.py) re-derive every probability from the stored odds/ratings, check that every open fixture has exactly one tier, that fallback is used only when no accepted market exists, that slot joins require competition+start+opponent, and that every rendered row carries a source link. The workflow runs them before publishing.

Limitations

Probabilities are estimates, not verified win probabilities or betting advice. Bookmaker prices move; the board shows the collection time on every page. Elisa group matches are Bo1 per Liquipedia, so single-map variance is higher. Fallback picks are materially weaker than A/B picks — that is why they are labelled and ranged.
