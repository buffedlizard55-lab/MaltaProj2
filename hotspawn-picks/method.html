⚙ Method — reverse engineering, formulas & 4-hour refresh

1. What 'every match on HotSpawn' means

The playable inventory is the CS2 fixtures rendered in play.hotspawn.com/lobby single-page app, whose data comes from its public fixtures API (upstream collectors record both the lobby transfer-state and a 12,016-row API pull; CS2 rows filtered by sportAlias=cs2 + current week). A match counts as open only if seen_in includes lobby_page and its lock is in the future. API-only rows (cancelled/started ghosts) go to Status Conflicts — see F4. This snapshot: week 273, 33 open.

2. Resolution ladder (featured first; fallback ONLY for gaps)

  1. Featured consensus (unchanged): Pinnacle (×2 weight)/Bovada/Melbet/Kalshi two-way match-winner prices, de-vigged, kickoff-verified. Copied byte-for-byte from data/f7279a54/board.json.
  2. HLTV: identity/schedule/roster confirmation. No odds feed exists; 403 bot outcome is logged, dated manual reads are cited.
  3. Fallback books/exchange: all captured quotes from both upstream snapshots (this run: 183 usable) re-joined with roster-verified alias groups only. Sponsor aliases require identical 5 starters on an official/registry page.
  4. Valve VRS model: official standings 2026_10_05 (380 teams). P(A)=1/(1+exp(-k·C·(ptsA-ptsB))), C from Valve's Glicko (RD 75).
  5. † Floor / blank: as defined on the Unresolved page.

3. No-vig + calibration numbers

Two-way de-vig (proportional): pA=(1/oddsA)/((1/oddsA)+(1/oddsB)); books with implied sum outside 0.94–1.30 are rejected. Kalshi: yes-mid $ → decimal 1/mid, books >10¢ spread rejected upstream.

Calibrated slope k = 0.4308 (least-squares vs bookmaker probabilities, n=60 pairs, MAE 7.7pp; unfitted Valve slope MAE 12.2pp — source: data/f7279a54/board.json (least-squares fit of fitted-VRS prob vs bookmaker no-vig prob)). Read model % as ±8–12pp. Fair odds = 1/p; American odds are display conversions of the same p.

4. Refresh architecture (every 4–8 hours, zero manual input)

Upstream Actions bots re-capture HotSpawn + books + VRS on their own schedules (~30 min–4h). This board's workflow .github/workflows/hotspawn-picks-f3e5123c.yml runs every 4 hours and after upstream board workflows: resolve.py → build.py → contract tests → commit board+site (own scope only, pull --rebase, never force-push). GitHub Pages then republishes. A snapshot older than 8h shows a red stale banner in your browser; locked matches roll off automatically because the lobby set is rebuilt each run.

Reproduce locally: python3 scripts/f3e5123c/resolve.py && python3 scripts/f3e5123c/build.py && python3 -m unittest tests.test_f3e5123c -v

5. Hard rules

  • HotSpawn crowd % never enters any probability (not collected into this board at all).
  • Unverified = blank + flagged; secondary aggregator numbers are leads, never prices.
  • Featured lines are immutable here; disagreement is displayed as a cross-check, never blended.
  • Every rendered row links its official sources (book/exchange page, Valve details file, HotSpawn match).
Probabilities come from OUTSIDE betting markets (Pinnacle/Bovada/Melbet/Thunderpick/Kalshi) de-vigged, or — only where no market exists — originated from official Valve VRS points. HotSpawn crowd % is never used as a probability. †Directional floor = rated team vs the last VRS team; a lower bound, not a betting line. Analysis for HotSpawn pick'em only — not betting advice.
