Method & verification

How each pick is produced and independently checked

1. The resolution ladder (no HotSpawn crowd input at any step)

  1. Featured bookmaker lines, unchanged. Pinnacle / Bovada / Melbet / Thunderpick decimal odds are converted to implied probabilities and de-vigged per book (p = (1/odds) / (1/odds_a + 1/odds_b)), then averaged across books.
  2. Other esportsbooks and betting lines. Name variants are joined only when the opponent and kick-off agree (90-minute tolerance), e.g. UNiTY/Apogee Esports joins.
  3. Kalshi regulated exchange. Used where no traditional book prices the fixture, with roster-verified aliases (HotSpawn “Zetta” = Kalshi “Alianza Lima Esports”).
  4. HLTV and bo3.gg identity checks. Team aliases and rosters are confirmed against HLTV team/match pages and bo3.gg before any join is accepted.
  5. Official Valve VRS origination. When no external price exists, p = 1 / (1 + exp(-k·C·Δpoints)) using Valve's published points, Valve's effective slope C and this project's fitted k (60 market pairs, MAE 7.70 pp).
  6. Labelled bounds. A team absent from Valve's table is at or below the published floor; the row shows ≥/≤.
  7. Explicit unresolved blank. If none of the above applies, the row stays blank and is published on the Unresolved page with its attempt ledger.

2. The constants, and where they really come from

Valve's model/glicko.js publishes Q = ln(10)/400 and model/fit.js fixes RD = 75 for the expected-win fit. The effective logistic slope is C = ln(10)·g(75)/400. This desk re-derives it live: 0.005600007780351016 vs the boards' quoted 0.0056000078 (match = True, diff 1.9648983828890465e-11). It is correct, but note it spans two files rather than appearing as a literal — see Flagged.

Calibration slope k = 0.43077894236569164 is this project's own fit of market prices against rating differences (60 pairs), not a Valve value.

3. The five hard verification gates (re-run every refresh)

  • Coverage: every open lobby fixture has a pick and both probabilities (14 pass).
  • Arithmetic: stored market consensus reproduces from decimal odds within 0.25 pp; originated probabilities reproduce from official points within 0.06 pp (14 pass).
  • Official identity: standing, points and five-man roster match the live Valve table for every originated row (9 pass).
  • Sources: at least one external source link plus the HotSpawn permalink (14 pass).
  • No crowd input: no row reads HotSpawn vote/crowd percentages (14 pass).

A failed gate flips the row to unverified, adds it to Flagged and (if it has no pick) to Unresolved. Values are never inferred or filled in.

4. Automation

Workflow cs2-picks-bce97e13.yml runs every four hours (and on upstream board refreshes): live Valve check → verification build → site render → tests → commit. No manual input.
