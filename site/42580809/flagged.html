F5. Sources that refuse automated access

  • Cloudflare/bot protection: HLTV (403), egamersworld.com match pages (403; the odds widget data is read from the collected JSON instead), Thunderpick (403), GG.BET (403), Oddspedia (403), 1xBet (403), Liquipedia (406), DraftKings (403), BetMGM (403), Caesars (403), Marathonbet (403), Betway (404).
  • Rate limited: Kambi-powered books (BetRivers US/CA, NordicBet, Betsson, OTO, Bethard) answered HTTP 429.
  • Unusable: Polymarket's open CS2 markets in the API response are stale (spring 2026) — collected as evidence, never used. Straight-list payloads above ~400 KB are truncated in the raw mirrors, so live values are always re-read by the runner rather than parsed from the mirror.
  • No request was authenticated, retried around a challenge, or routed past a block.

F6. Data-source discrepancies

  • The lobby UI's counters (All 90 · S 4 · B 26 · C 60) disagree slightly with the 92 CS2 rows its own JSON API returns for the same window. The API is used here; the difference is recorded, not reconciled.
  • Kalshi's occurrence_datetime runs up to four hours later than the schedule written in its own settlement rule, so matching uses the rule text and ignores that field.
  • Aggregator rows are the weakest evidence on the board; they are labelled as fallback on every card and counted separately in the coverage tables.
  • Board rows can change between refreshes as books move; each card prints the timestamp of its own read.

F7. Ambiguous team names in Valve's official standings (31 names)

Valve's standings list some team names twice with different rosters and different points, so a fixture cannot be tied to one entry. Rather than guess, the originated model refuses those names; if a match needs one, the row stays blank.
